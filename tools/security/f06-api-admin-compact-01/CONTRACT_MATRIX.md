# SECURITY-F06-API-ADMIN-COMPACT-01 — مصفوفة المصدر G1

الحكم: `G1_SOURCE_CONTRACT=PASS_SCOPED`. المرجع شيفرة API الحالية فقط؛ دليل A5 السابق تاريخي. ترجع جميع الاستجابات الناجحة من controllers الحالية ومعها `meta.request_id`. المعاملة تبدأ في `TenantStaffRequestContext` قبل الخدمة وتُحسم commit/rollback فيها. `OFF` يستخدم `pgsql_tenant_runtime` القديم؛ `ON` يبدّل إلى LOGIN محدد بـ`session_user` ثم يعيد config في `finally`.

| المسار | الخدمة/الإذن | العملية والحدود تحت المصدر | ON المطلوب واختبار القبول |
|---|---|---|---|
| `GET /api/v1/company/roles` | `TenantStaffCompanyRolesController` → `TenantStaffAuthorizationService::listRoles`؛ `role.view` | roles ACTIVE وغير مؤرشفة للشركة، `id/name` | G4-A قراءة A5 حقيقية وبـA/B؛ لا كتابة |
| `POST /api/v1/company/roles` | `TenantStaffRoleManagementController::store` → `TenantStaffRoleMutationService::createRole`؛ `role.manage` | slug فريد، INSERT role، audit `role_created`؛ 201 و`data.id` | G4-B دالة create محددة، actor SQL لا INSERT مباشر؛ duplicate/tenant/audit |
| `PATCH /api/v1/company/roles/{role}` | `updateGrants` → `updateRoleGrants`؛ `role.manage` | role ACTIVE مع lock، منع تعديل دور الذات، `canDelegate` لكل grant، رفض مفتاح مكرر، استبدال grants، `roles.version+1`، invariant، audit؛ 200 `UPDATED` | G4-B دالة محددة تحافظ على contract؛ SELF/ALL_TENANT/nondelegable وسلبية دور الذات |
| `DELETE /api/v1/company/roles/{role}` | `archive` → `archiveRole`؛ `role.manage` | role ACTIVE، منع دور الذات، `status=ARCHIVED` و`archived_at` و`version+1`، invariant، audit؛ 200 `ARCHIVED` | G4-B دالة محددة؛ لا حذف فعلي ولا كسر آخر مدير |
| `GET /api/v1/company/staff` | `TenantStaffMemberController::index` → `TenantStaffAccountService::listStaff`؛ `member.view` | عضويات الشركة مع email/name/status | G4-A بيانات A5 موجبة وB غير مرئية، 403 لغير المخوّل |
| `POST /api/v1/company/staff` | `store` → `createStaffMember`؛ `member.manage` | email/name/initial_password إلزامية، factory Argon2id، user+membership، audit، role اختياري؛ 201 IDs | G4-D **مشروطة**: لا mapping Actor SQL للعضو الجديد؛ تتطلب قرار provisioning قبل ادعاء تكافؤ login تحت ON |
| `POST /api/v1/company/staff/{membership}/disable` و`reactivate` | `TenantStaffMemberController` → `TenantStaffAccountService`؛ `member.manage` | منع الذات، target ACTIVE↔SUSPENDED، `authorization_version+1`، invariant عند disable، audit واحد؛ 200 | G4-C دالتان محددتان، تحقق invalid session بعد تغير النسخة |
| `POST /api/v1/company/staff/{membership}/roles` و`DELETE .../roles/{role}` | `TenantStaffRoleManagementController` → `TenantStaffRoleMutationService`؛ `member.manage` | target≠actor، role ACTIVE، `canDelegate` لكل grant عند assign، row insert/revoke، `authorization_version+1`، invariant/audit؛ 201/200 | G4-C دالة assign/revoke محددة؛ role tenant/self/revoked/duplicate |
| `POST /api/v1/company/staff/{membership}/permissions` و`DELETE .../permissions/{permission}` | controller → `grantPermission/revokePermission`؛ `member.manage` | target≠actor؛ grant يتطلب `canDelegate`؛ active grant/version/audit؛ 201 `GRANTED` و200 `REVOKED` | G4-A إعادة `leads.view:SELF` الضيقة فقط؛ 050 overlay الحالية لا تدعم أنواعًا عامة |

`TenantStaffAuthorizationService::effectiveGrants` يضم role+direct للـACTIVE فقط ويفشل snapshot غير صالح. `canDelegate` يرفض `company.administer` و`TEAM/NONE` والنطاق الأعلى من المملوك، ويتطلب catalog ACTIVE/delegable/allowed_scopes. A5 الصناعية تحمل `role.manage/member.manage/role.view/member.view/leads.view:SELF` بدور fixture ولا تحمل `company.administer`. A0 مرساة invariant بلا SQL LOGIN؛ ليست مدير HTTP. الدالة 050 تقصر direct mutation على `leads.view:SELF` بـ`session_user`، ولا تبرر تعميمها.

اختيار G2: استثناء typed صغير لتصنيف غياب اعتماد SQL أو mapping خادم وغياب وظيفة overlay؛ الـmapper يعطي 503 عامًا، مع reason داخلي منقح. بديل service account عام أو وظيفة SQL عامة يفتح مصدر السلطة؛ مرفوض. لا حاجة لتغيير routes/controller أو permission catalog أو config أو migration. نجاح G2a source/lint لا يرفع G2 دون HTTP حقيقي على Sandbox جديدة. في G4، تنشأ فقط دوال SQL محددة وbranches في خدمات العمليات التي ثبتت، وتبقى OFF كما هي. عند اتساع contract أو حاجة provisioning منتج تتوقف الشريحة المعنية بنتيجة جزئية.
